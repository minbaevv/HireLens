# Закрытие брошенных интервью

## Зачем

Кандидат открывает интервью, отвечает на часть вопросов и закрывает вкладку.
Проверка лимита времени в коде срабатывает только в момент, когда кандидат присылает
следующий ответ. Не вернулся — интервью навсегда остаётся в `in_progress`,
ответы не оцениваются, а кандидат висит в воронке в статусе «Интервью».

Скрипт раз в 15 минут находит такие записи и завершает их штатной функцией
`finish_interview` — той же, что работает при истечении времени на странице кандидата.
Ответы, которые человек успел дать, оцениваются, кандидат переходит в «Оценены».

## Что входит

- `backend/app/scripts/close_abandoned_interviews.py` — сама задача
- `backend/app/scripts/__init__.py`
- `scripts/hirelens-close-abandoned.sh` — обёртка для cron

Миграций нет. Новых HTTP-эндпоинтов нет — снаружи задачу дёрнуть нельзя.

## Установка

1. Распаковать архив в корень проекта (`/root/HireLens`).
2. Сделать обёртку исполняемой: `chmod +x scripts/hirelens-close-abandoned.sh`
3. Пересобрать бэкенд (файлы копируются в образ).
4. Прогнать вручную один раз, проверить вывод.
5. Добавить в cron:

```
*/15 * * * * /root/HireLens/scripts/hirelens-close-abandoned.sh >> /root/backups/abandoned.log 2>&1
```

## Ручной запуск

```
docker compose exec -T backend python -m app.scripts.close_abandoned_interviews
```

## Поведение

- Берёт интервью со статусом `in_progress`, у которых `started_at` старше
  `INTERVIEW_TIME_LIMIT_MINUTES` + 5 минут запаса (по умолчанию 30 + 5 = 35 минут).
- Интервью, которые идут прямо сейчас, не трогает.
- Идемпотентно: повторный запуск безопасен, уже завершённые пропускаются.
- Падение на одном интервью не останавливает остальные.
- Если контейнер бэкенда не запущен, обёртка тихо выходит без ошибки.

## Журнал

`/root/backups/abandoned.log` — смотреть так: `tail -30 /root/backups/abandoned.log`
