## [2026-07-16] — Anti-cheat ↔ рекомендация + всё время по Бишкеку

### Added
- **Anti-cheat теперь влияет на рекомендацию (C1.1).** При `anti_cheat_score ≥ ANTI_CHEAT_DOWNGRADE_THRESHOLD` (по умолчанию 85) авто-рекомендация «hire» понижается до «maybe», кандидат помечается на очную проверку (`requires_manual_review`), а в bias-флаги добавляется «⚠️ Высокий риск списывания (N/100) — проверить очно». **Балл кандидата не меняется** (он отражает качество ответов). Понижение учитывается в уведомлениях (Telegram/email) и вебхуках. Порог настраивается через env.

### Changed
- **Всё время — по Бишкеку (Asia/Bishkek, UTC+6).** `SCHEDULING_TIMEZONE` по умолчанию теперь `Asia/Bishkek`. Слоты планировщика, выбор слота (datetime-local) и отображение дат на фронте (кандидаты, вакансии, биллинг, админ, интеграции) — в бишкекском времени независимо от таймзоны браузера. PDF-отчёт (дата подачи, «Сгенерировано») и CSV-экспорт — тоже по Бишкеку. Новый модуль `frontend/src/utils/datetime.js` (`fmtDate`/`fmtDateTime`/`toInputValue`/`inputValueToISO`).

## [2026-07-16] — КРИТ: починен скоринг (регрессия v38)

### Fixed
- **Скоринг снова считает оценки (technical/soft/experience/motivation).** В v38 в промпт скоринга попал литеральный JSON `{"category": ...}` с одинарными скобками, а промпт прогоняется через `.format()` → `KeyError: '"category"'`. Скоринг падал у ВСЕХ кандидатов с v38, поэтому оценки были пустые, а кандидат уходил в «ручную проверку». Скобки заэкранированы (`{{ }}`).

## [2026-07-16] — Google Calendar (freeBusy 403) + страховка скоринга

### Fixed
- **«Свободные слоты» больше не дают 403 Forbidden.** Запрос `freeBusy` требует доступа на чтение календаря — в scope добавлен `calendar.readonly` (раньше был только `calendar.events`). **Нужно переподключить Google** (Отключить → Подключить), чтобы выдать новый scope.
- **Кандидат больше не «виснет» в статусе «Интервью».** Если фоновый скоринг падал до внутреннего обработчика ошибок, кандидат оставался в `interviewing` навечно. Теперь `_run_scoring_task` переводит его в `completed` + `requires_manual_review`.

### Docs
- `GOOGLE_CALENDAR_SETUP.md`: redirect URI исправлен на поддомен `api.gethirelens.tech` (callback идёт на backend), добавлен scope `calendar.readonly`.
- `ROADMAP.md`: добавлен отложенный план feature-gating по тарифам (флаг `FEATURE_GATING_ENABLED`, default OFF, включается с платежами).

## [2026-07-15] — Фикс отчёта red flags (ложные флаги)

### Fixed
- **«Кандидаты с флагами» больше не показывают ложные флаги.** Модель иногда возвращала заглушку `{"category":"other","detail":"Нет значимых красных флагов"}`, и кандидат попадал в отчёт как «с флагом».
- **Сырые теги `[skill_gap]` / `[other]` заменены на читаемые метки** («Пробел в навыках: ...», «Честность: ...» и т.д.).
- Новый модуль `app/ai/red_flags.py`: единая очистка шума (`is_noise_detail`), читаемые метки (`format_red_flag`) и очистка старых записей (`clean_flag_string`).
- Фильтрация применяется на чтении в `/analytics/bias-report`, поэтому **старые ложные флаги тоже исчезают** без перескоринга.
- Промпт скоринга (`prompts.py`): убрана заглушка-пример `[{"category":"other","detail":""}]` → `[]`, добавлена явная инструкция не выдумывать «нет флагов»-записи.

## [2026-07-14] — D2: публичный API + webhooks

### Added
- **Публичный REST API `/api/v1`** — read-only доступ для внешних систем (CRM/ATS): `GET /ping`, `/jobs`, `/jobs/{id}`, `/candidates`, `/candidates/{id}`. Авторизация по API-ключу в заголовке `X-API-Key`. Данные строго изолированы по компании-владельцу ключа.
- **API-ключи** — выпуск/отзыв (`/integrations/api-keys`). Ключ вида `hl_…` показывается один раз; в БД хранится только SHA-256 хеш + префикс. Отозванные или ключи с истёкшей подпиской отклоняются (401/402).
- **Webhooks** — подписка на события `interview.completed`, `candidate.scored`, `candidate.created` (`/integrations/webhooks`). POST с JSON-телом, подписанным HMAC-SHA256 (`X-HireLens-Signature: sha256=…`), 2 попытки, журнал доставок, кнопка «Тест». secret показывается один раз.
- **SSRF-защита webhooks** — только http/https, в production только https; приватные/loopback/link-local адреса блокируются (настройки `WEBHOOK_TIMEOUT_SECONDS`, `WEBHOOK_ALLOW_PRIVATE_URLS`).
- **Страница «Интеграции»** в кабинете (RU/KY/EN) — управление API-ключами и webhooks, только для роли admin.
- **Документация API** — [API.md](./API.md) с описанием эндпоинтов, авторизации и проверки подписи webhook.
- **Тесты** — `test_integrations.py`: выпуск/отзыв ключей, авторизация публичного API, валидация URL/событий, HMAC-подпись, тестовая доставка (с моком httpx).
